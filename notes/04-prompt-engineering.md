# Part 04：Prompt Engineering

## 消息角色

- `system`：规定助手身份、任务、输出要求和行为边界。
- `user`：用户的请求或待处理数据。
- `assistant`：模型生成的回答，也可作为历史消息重新发送。

System 消息仍然是上下文中的文本，不是无法绕过的程序权限系统。

## 一个可复用的 Prompt 结构

```text
角色
→ 任务
→ 输入或上下文
→ 约束
→ 输出格式
→ 信息不足时如何处理
```

## Zero-shot 与 Few-shot

- Zero-shot：只描述任务，不给示例。
- One-shot：提供一个示例。
- Few-shot：提供多个示例，引导输出格式和判断模式。

示例本身如果存在偏差，模型也可能沿着相同方向产生偏差。

## JSON 输出不能只靠 Prompt

“请输出 JSON”只能提高生成正确格式的概率。程序仍然需要：

1. 使用 `json.loads()` 解析。
2. 检查必需字段。
3. 检查字段类型。
4. 检查枚举、范围和业务规则。
5. 失败时重试或返回明确错误。

示例约束：

```json
{
  "category": "knowledge | calculation | writing | other",
  "summary": "15字左右的问题摘要",
  "needs_clarification": false
}
```

## Prompt 与代码的分工

Prompt 适合规定：

- 角色和语气
- 任务步骤
- 输出格式
- 示例和解释方式

代码必须负责：

- 输入和输出校验
- 工具白名单
- 权限控制
- 超时和重试
- 异常处理
- 副作用确认

## 待补实践

结构化输出还应覆盖正常、空、模糊、超长、特殊字符和提示注入等输入，并以解析与字段校验结果作为通过标准，而不是只凭肉眼判断“看起来像 JSON”。
