# Part 01：LLM 基础

## 必须理解的概念

### LLM 的输入和输出

文本模型接收 Token 序列，根据已经训练好的参数预测下一个 Token 的概率分布，再把生成的 Token 追加到上下文中继续预测。

这叫自回归生成。生成过程不会自动修改模型参数，因此不等于继续训练或学习。

### Token

Token 是模型处理文本的基本单位，可能是一个词、词的一部分、标点或字符。Token 不等于固定意义上的“单词”或“最小字符”。

### 上下文窗口

上下文窗口限制一次请求可以处理的 Token 总量，通常包括：

- System 消息
- 用户输入
- 历史对话
- 工具结果
- 模型输出需要预留的空间

### 为什么会产生幻觉

LLM 的目标是生成统计上合理的后续内容，而不是自动查询事实数据库。流畅、完整、逻辑自洽的回答仍然可能不符合事实。

## 关键边界

```text
模型生成 Python 代码 ≠ Python 代码已经执行
模型描述一个动作 ≠ 动作已经发生
模型回答很确定 ≠ 回答已经经过事实验证
```

Computer Use 或 Function Calling 也没有改变这个边界：模型提出结构化动作，外部运行时负责校验、授权和执行。

## 一次 API 请求

```text
用户输入
  → Python 程序 / SDK
  → HTTP API
  → Tokenizer
  → LLM 逐 Token 生成
  → 解码为文本
  → Python 显示结果
```

## 学习纠正

- 把输出 Token 加入下一步输入，是生成过程，不是模型继续训练。
- 相同输入可能因为采样策略得到不同输出。
- 超过上下文窗口可能导致请求失败、历史被裁剪或模型无法利用早期信息。
