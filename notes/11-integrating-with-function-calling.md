# Part11：Function Calling

## 为什么这样设计？

Part07 的 LLM 只能根据对话生成文本，不能可靠计算、获取实时数据或真正执行动作。

Part11 把“理解与决策”交给 LLM，把“校验与执行”交给 Python：

```text
用户提出需求 → LLM 选择工具并生成参数 → Python 校验并执行
→ 执行结果返回 LLM → LLM 组织最终回答
```

核心原则：**LLM 负责判断做什么，Python 负责可靠地做。**

## 相比 Part07 的进步

- 从“只生成文本”进步到“生成结构化工具请求”。
- 从“依赖训练数据”进步到“获取外部实时数据”。
- 从“声称完成动作”进步到“真正执行计算、写文件等操作”。
- 工具白名单、参数校验和异常处理让执行过程可控、可验证。

## 这一章着重要学什么？

1. 用工具描述告诉模型有哪些函数、各自需要什么参数。
2. 理解模型不会执行函数，只会返回工具名和参数。
3. 用 Python 校验工具名和参数，再调用真实函数。
4. 用 `call_id` 把工具结果与原请求配对，并交还模型。
5. 建立完整闭环：模型请求工具 → Python 执行 → 模型解释结果。

## Function Calling 主要解决什么问题？
- 1.一致的响应格式
- 2.拿到外部数据

## messages保存哪些内容？
- 1.用户问了什么
- 2.模型之前回答了什么
- 3.模型请求过哪个工具
- 4.Python 返回了什么工具结果
这样，模型才能看懂完整过程
